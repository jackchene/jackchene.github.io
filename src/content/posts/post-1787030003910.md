# 教材 RAG 里 BM25 分词策略的影响

RAG 检索的任务是让系统能通过关键词从文本找到用户问题的答案出处。我把 BM25 这条关键词通道单独拎出来做了一轮对照实验，结论和最初预想的不太一样。

## S，情境，先交代 BM25 是什么

BM25 是目前最常用的关键词相关性排序算法，Elasticsearch 和多数 RAG 系统的关键词通道都用它。它给一篇文档打分，依据三个信号。词频，查询词在文档里出现多少次。逆文档频率，这个词在整个语料里有多稀有。文档长度，同样命中在长文里比在短文里含金量低。三个信号合起来，衡量文档和查询在词面上的匹配程度。

公式长这样。

```
score(D,Q) = Σ  IDF(q) ×  f(q,D)·(k1+1) / (f(q,D) + k1·(1-b+b·|D|/avgdl))
IDF(q) = ln((N - n(q) + 0.5)/(n(q) + 0.5) + 1)
```

k1 控制词频饱和，出现很多次之后分数不再线性上涨。b 控制文档长度归一化，长文档的命中次数会被按比例压低。BM25 是 TF-IDF 的升级版，TF-IDF 是它在词频不饱和、长度不惩罚这两个极端条件下的特例。

这套算法有个前提，它统计的是 term，也就是"词"。英文空格天然分好词，中文没有。整句中文如果被当成一个 term，BM25 就完全失效。这是这次实验的起点，中文教材用 BM25 之前，必须先解决分词。

## T，任务，指标怎么算

召回效果用什么衡量，我定了四个指标。Hit@1，正确答案出现在第一名。Hit@3，出现在前三。Hit@5，出现在前五。MRR，正确答案第一次出现位置的倒数，衡量整体排序质量。这四个指标都看同一个东西，正确答案有没有被 BM25 排到前面。

为了让指标有意义，还要有稳定的 ground truth。我从每本教材的定义句所在的 chunk 里手动挑出答案，写脚本校验这个 chunk 确实属于对应教材，再把 query 按提问方式分成三类。术语精确型，直接问教材里写明白的概念。描述改写型，绕开术语用日常说法问。口语变体型，带俗称、公式和符号，比如摩尔、mol、牛二。

实验要回答三个问题。中文是不是必须分词。领域词典有没有用。同义词归一化和分词到底是不是一件事。

## A，行动，实验怎么设计


语料三本教材。化学必修第一册 199 个 chunk，物理必修第一册 221 个，英语必修第一册 408 个，合计 828 个。query 41 条，中文 34 条、英语 7 条。把英语加进来，是为了看语言差异对分词策略的影响。

对照组按变量递增排了五组，每组只比上一组多一个变化。S1 英文式空白切分，中英文都按空格切，当零假设。S2 所有文本都交给 jieba。S3 中文 jieba 加目录浅词典，浅词典从章节标题里清洗出来。S4 中文 jieba 加 agent 词典和同义词映射。S5 按 book 区分语种，中文走 S4，英文走一个不引入新依赖的简易分词器，标点剥离加后缀还原。

agent 词典是让模型通读教材后产出的。标准术语单独放到 agent_dict.json，每条带 confidence 和证据 chunk。同义词关系单独建一张映射表，alias 指向 canonical，confidence 低于 0.7 的过滤，有歧义的映射保留但打上模糊标记。分词和归一化分成两步，文档和 query 先各自切词，再统一把别名换成标准术语。

## R，结果，结论是什么

五组策略跑完，总体指标如下。

| 策略 | Hit@1 | Hit@3 | Hit@5 | MRR |
|---|---:|---:|---:|---:|
| S1 英文式切分 | 4.9% | 9.8% | 9.8% | 0.069 |
| S2 jieba | 36.6% | 56.1% | 70.7% | 0.487 |
| S3 加浅词典 | 39.0% | 58.5% | 70.7% | 0.503 |
| S4 加agent词典与映射 | 39.0% | 56.1% | 73.2% | 0.504 |
| S5 按语种混合 | 41.5% | 58.5% | 70.7% | 0.519 |

结论有三条。

第一条，中文必须先分词。S1 在中文 34 条 query 上 hit 全部为 0，在英文 7 条上 hit@3 却到 57.1%。同一套切分逻辑，中文整句被当成一个 term，英文天然有空格，两种语言在 BM25 眼里的起点完全不一样。这是语言结构决定的，调参解决不了。

第二条，词典有收益，但会饱和。S3 到 S4，化学 hit@5 从 88.2% 升到 94.1%，物理 hit@3 从 35.3% 升到 41.2%。收益大部分来自词边界被补对，同义词映射的贡献集中在口语变体这一类，C 类 hit@5 从 30% 升到 40%。同一改动在不同 query 类型上的收益分布不一样，不看分组数据容易得出偏颇结论。

第三条，分词和同义词是两件事，混在一起做会互相拆台。第一版实验我把模型生成的术语和俗称全塞进 jieba，结果 hit@3 反而下降。有个 query 叫 mol质量怎么求，jieba 自己切的时候，query 里的质量能和正文里的摩尔质量搭上边。词典一加进去，mol 被当成物质的量的变体单独切出来，query 侧 term 变成 mol 和物质的量，跟正文失去交集，目标 chunk 掉出前三。分词器负责切词，同义词负责等义，让同一个工具一起干，它不知道摩尔等于物质的量。把同义词挪到分词后的归一化阶段，这个 case 就消失了。

S5 按语种混合是唯一同时处理两种语言的。英文语料 hit@1 从 28.6% 升到 42.9%，中英混排 query 在两侧都吃了一点亏，纯英文 query 的收益把损失补了回来。语料同时含中文和英文时，坚持一个分词器处理所有语言，等于默认两种语言的 term 结构可以共用一套规则，这个假设在数据上不成立。
